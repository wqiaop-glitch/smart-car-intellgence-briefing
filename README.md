# 智能汽车竞品周报

本仓库保存第 01 期周报页面，以及从页面导出的 JSON、YAML 数据。

- 原刊周期：2026.10.09—2026.10.15。
- 数据导出日期：2026.10.20。
- 覆盖范围沿用原刊：吉利及旗下品牌以外的汽车智能化动态。

## 文件

| 文件 | 用途 |
| --- | --- |
| `index.html` | 原始周报页面，包含样式、内容与筛选逻辑，可直接用浏览器打开 |
| `data/report.json` | 从 HTML 导出的结构化数据 |
| `data/report.yaml` | 与 JSON 内容相同的 YAML 表示 |
| `README.md` | 使用方法和数据限制 |
| `.gitignore` | 排除本地系统文件、环境变量文件及部署配置 |

## 数据状态

本次工作是对现有 HTML 的格式导出，没有重新搜索或核验新闻、日期、参数、
来源链接与洞察。数据中的 `verification_status: not_reverified_in_export`
明确记录这一点。不能将“有来源链接”视为“已核验”。

原页面含 11 条动态，其中包括需要核实的条目。本次保留原文与备注，
未补造证据、版本号或原文未提供的日期。发布状态字段为原页面表述，
不保证符合后续 Agent 提示词中的规范枚举。

原刊周期不是周一到周日，导出时没有更改。未来按每周一生成周报时，
应单独计算上一完整周，不能套用本期日期。

JSON、YAML 包含 `items`（情报）、`observations_as_published`（原刊观察）、
`followups_as_published`（原刊跟进）及来源说明。S01 等情报 ID 在本次导出时分配。

## 本地查看与编辑

直接用浏览器打开 `index.html`，无需安装依赖或配置 API Key。

当前页面是独立静态文件，不会自动读取 `data/report.json` 或
`data/report.yaml`。修改数据文件不会自动更新页面；如需每周自动生成，
应另行实现或接入经过检查的生成脚本。

此前对话中的公司 Agent 提示词是一份执行规范，不表示本仓库已实现该流程。
本包不包含公司电脑上的 `generate.js`、定时任务或其 YAML 格式；
本包导出的数据格式也未验证与公司现有脚本兼容。

## 上传 GitHub

1. 在 GitHub 创建目标仓库，按团队要求选择可见性。
2. 解压上传包，在仓库中选择上传文件。
3. 上传本文件所在文件夹的内容，保留 `data/` 子目录；
   确保 `index.html` 和 `README.md` 位于仓库根目录。
4. 提交后，GitHub 可显示 README 和数据文件；网页在线浏览需要另行配置静态站点托管。

本包没有包含旧 Sites 的 `.openai/hosting.json`、Git 历史、
登录凭据或本地绝对路径配置。它也不包含新闻源全文；来源链接保留在情报中。
